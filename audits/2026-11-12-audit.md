## Refuted

Important | tests | scripts/install-hooks.sh:150 | The code that merges and removes entries in the user's global ~/.claude/settings.json (add_entry, drop_entry, entry_present, has_entry, write_settings) is never run by any test. | install-hooks-token.test.ts covers only the token block, and always with `--dry-run`. Nothing covers idempotent re-install (the comment at :138-141 says the byte-identical `$HOME` command string is what stops duplicate entries), the double PermissionRequest/Notification registration (:183-186), the `.matcher // ""` merge into an existing matcher group (:156-160), or `--uninstall` pruning empty groups and events (:171-182). This jq rewrites a file shared with every other Claude Code setting.

**Refutation:** The "never run by any test" claim is false as stated. Every case in test/install-hooks-token.test.ts calls runInstaller (line 120), which runs the whole of scripts/install-hooks.sh with `--dry-run` against a scratch CLAUDE_CONFIG_DIR. So the settings loop at :230-256 does run: entry_present, add_entry (on an empty `{}`) and write_settings (its jq validation at :197, then the DRY early return) all execute. What is true is narrower: no test asserts the merged JSON, no case starts from an existing settings.json (so the idempotent re-install and the merge-into-an-existing-matcher-group branch never execute), and no case passes `--uninstall` (so drop_entry and has_entry never run). A finding scoped to that would stand.
