Management › Git: five ways to make it answer “what needs me?”

An analysis of the shipped Git tab, as drawn in docs/guides/mockups/redesign-mock.html (Cards, Table and Triage), then five redesigns. All five use the same fixture: seven pinned repos plus three live sessions. Every artboard responds to clicks. Git operations still go through Sync (the git-sync session); nothing here pulls or pushes on its own.

Analysis of the current tab

Cards (default)One card per pin in pin order. The head carries the branch and upstream chips, a facts row holds the dirty, trunk and fetched chips, and up to five branch rows follow.
TableSeven columns, and rows expand to show branches. At a 1280px window the Fetched and Sync columns sit behind a horizontal scroll.
TriageGrouped into Needs you, In flight, Quiet and Can't read. It is the only layout that ranks repos, but it isn't the default.
ToolbarCards | Table | Triage, plus the SYNC 12s · FETCH 3:12 clock chip and its popover.

Findings

    V1

    Inbox

    Recommended

    One ranked list replaces the three layouts. Each repo that needs you gets a verdict sentence, its problems as steps, and one primary key worded for the problem. Repos with nothing wrong share one dashed line each. Dead pins get an inline Unpin. The counts at the top double as filters. The page also reads the sessions: uncommitted work on a branch where an agent is working is expected, so it gets calm wording and is not escalated.

    Gains
    • One glance gives the answer, and the counts give the size of the problem.
    • No layout to choose, so the persisted gitLayout setting goes away.
    • Built on gitTriage.ts and gitStatsText.ts as they are, plus a problems → steps mapper.
    Costs
    • Comparing repos side by side gets harder than in Table.
    • Branch lists sit behind a toggle by default.
    • The verdict copy needs a careful text table and tests.
    V2

    Health matrix

    Dense

    This is Table with the chips taken out. Each column is one health check with a fixed meaning, and a healthy cell is a faint dot, so only problems carry colour and text. Column headers count the failures. The repo, check and action columns fit in 960px. Click a row to open its branches with labelled ↓/↑.

    Gains
    • The fastest scan across many repos, and it scales to 20+ pins.
    • Problems pop out because healthy cells say nothing.
    • Small change to the existing GitTable.
    Costs
    • It still says what is wrong but not what to do.
    • Needs a phone fallback, which here is an inner scroll.
    • Six columns to learn.
    V3

    Split inspector

    Matches Sessions

    This reuses the Sessions split pattern: a ranked list on the left, each repo with its worst problem as a subtitle, and an inspector on the right. The inspector shows four check tiles (Working tree, Your branch, Trunk, Origin data), each with a hint, then branches split into Active and Stale, with the session badges and a Clean up via Sync key for stale and merged branches.

    Gains
    • Room for full detail and explanations without crowding the list.
    • Same mental model as Sessions, so nothing new to learn.
    • The natural home for future per-repo actions such as log, prune and open in editor.
    Costs
    • One repo in depth at a time, so you click through.
    • Stacks on a phone, and the list → detail flow needs a back affordance.
    V4

    Branch board

    Branch-first

    The unit changes from repo to branch. Every open branch across every pin is placed in a column by what it needs: Agent on it, Ready (0 behind trunk), Drifting (behind trunk, recent) and Stale (≥ 20 behind or idle ≥ 7 days). Repo-level problems shrink to a pill strip above the board. This answers “what am I working on, and what should I land or delete?”

    Gains
    • The only variant that makes branch hygiene a first-class view.
    • Mirrors the Sessions board, and the session badges make the link obvious.
    • Shows work in flight across repos at a glance.
    Costs
    • Repo health (dirty, auth) is pushed to a strip and gets less weight.
    • The 50-branch cap per repo can overflow the columns.
    • Needs new thresholds (stale), and those need agreeing.
    V5

    Refined cards

    Lowest cost

    Keeps Cards and fixes what hurts. Cards are sorted by severity. Each gets a one-line verdict under the name and shows only problem chips, so “clean” and “main = origin” are gone. A fetch error becomes a banner with Retry. Branches get labelled columns (↓ behind · ahead ↑), and stale ones fade. Dead pins collapse into one footer with Unpin. The clock chip becomes a plain freshness line.

    Gains
    • Smallest diff: GitCards, GitParts and GitClockChip.
    • Keeps the grid people already know.
    • Each fix can ship on its own.
    Costs
    • The page still has no single answer or summary.
    • Cards stay tall, so with more than six pins you scroll.
    • Table and Triage remain, along with the choice between them.
