Git Sync Button

Management › Git. Two things to fix: the Sync control is drawn with the branch chip's exact recipe (12px/500, 1px --hairline2, 999px corners, card paper), so a reader cannot tell a fact from an action; and the card head wraps, so Sync sits on line 1 or line 2 depending on how long the repo name is. Three button treatments below, one rejected, then the two ways to pin the head. Every mock uses the real class names and tokens.

Where Sync lives: the right end of a card head · the right end of a busy Triage row's head · beside a quiet Triage row's line · the Table's last column. Only the first two wrap today. States: Sync (idle) · Syncing (running: tinted and turning, click opens the chat; no "open" suffix, the tint says it) · Syncing… (launching, disabled) · Starting… (mid-POST, disabled).

Now

the problem

Same card width. backlog-manager has the longer name, so "fetched · Sync" drops to a second line; on brickwright it fits on the first. And in both, Sync and main are the same pill.

A · Ink fill

heaviest

The app's primary-action grammar (New session, Send, the + key: --ink fill, --strip text, square-ish corners) shrunk to row size. Running turns --cyan, as the spawn Send does. Unmistakable, but a board of eight repos gets eight black buttons fighting the repo names for attention, and Sync is a per-row chore, not the page's one action.

B · Raised key

recommended

A key on the paper: --strip-hi fill, 8px corners, no border, a two-arrow glyph. The grammar becomes square with a glyph = action, round and outlined = fact, which is what .seg already does one level up. Running tints it cyan and spins the glyph (still under prefers-reduced-motion). Medium weight: visible on every card, dominant on none. The glyph is not the band's ↻, which means "re-read stats".

C · Text action

lightest

Sync as cyan text, the way the card already writes "+N more" and the empty state writes "Pinned": --cyan is the one interactive accent, so colour alone says action. Nothing can be mistaken for a chip. Costs discoverability, and on a phone the tap target is invisible padding; the running state leans on the glyph spin to be noticed.

D · Icon only

rejected

One glyph, no word. Rejected because the band already has a 26px round ↻ meaning "refresh now, re-read the stats"; a second circle-with-arrows per card that means "launch a git-sync session" is two look-alikes with different costs, and a stray tap here spends a session.

↻band: refresh stats card: launch a sync

Pinning the head

Both fixes replace the wrapping flex head with a grid: dot | name + chip (wrapping inside its own column) | end. The end column is pinned to the first line, so Sync never moves. They differ in what the end column holds.

H1 · fetched stays in the head

Nothing moves between rows. When the card is tight the main chip drops under the name instead, so the first line is name · fetched · Sync and the chip starts line 2. The head grows by a line on narrow cards.

H2 · fetched joins the facts row recommended

"fetched 1d ago" is a fact about the data, like "clean" and "main = origin", so it sits at the right end of that row, muted. The head is then name · chip | Sync and fits one line down to a phone-width card. Triage busy rows get the same; the Table keeps its Fetched column.
