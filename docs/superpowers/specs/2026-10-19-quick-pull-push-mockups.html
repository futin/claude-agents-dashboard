Quick pull and push without a Claude session

Sync starts a full /git-sync session every time: a secret scan, checks, branch pruning, a question round. Many rows only need one git command. Each variant below adds a fast path that runs plain git on the server and leaves Sync for everything else. Click the buttons and pills to see the running and finished states.

Which pill gets a fast path

same rules in every variant

A fast path only exists when git can do it with no judgement call: a fast-forward or a plain push. Anything that needs a commit, a merge or a PR stays with Sync.

A · The pill is the button

your idea

A pill with a fast path gains a small arrow and a hover ring. Clicking it runs the command; the pill turns cyan while git runs, then settles to its healthy text. Pills without a fast path look exactly as today. Sync stays at the end of the row.

Good

  • No new chrome: the action sits on the fact it fixes.
  • Two problems on one row (row 4) are two separate clicks, each obvious.

Costs

  • Matrix only. Inbox, Inspector and Branches draw facts differently and need their own version.
  • A pill that looks like a status but acts like a button can surprise; the arrow is the only cue.
  • Phone: Matrix scrolls sideways, so the pill can be off-screen.

B · A quick key beside Sync

recommended

The action column gets one more key, built from the same rules: Pull, Push or Pull + push, with the count. When the quick key fixes everything on the row it takes the dark primary style and Sync goes quiet. A diverged or PR-only row gets no quick key.

Good

  • Lives in GitKeys, which every layout already draws, so Inbox, Inspector and Branches get it for free.
  • Reads as a button: same shape as Sync and Retry fetch.
  • One click for the common case.

Costs

  • The action column grows by about 80px.
  • The key does not point at which pill it fixes; the label carries that.

C · Sync becomes a split button

Sync keeps its place and gains a caret. The menu lists Pull and Push with what each would do, greyed out with a reason when git cannot do it, and the full Claude sync at the bottom. Row 1's menu is open.

Good

  • Row width unchanged.
  • Room to explain each command and why one is unavailable.

Costs

  • Two clicks for the most common case.
  • The fast path is hidden until you open the menu.

Left out · A git console per repo

YAGNI

A drawer per repo with Fetch, Pull, Push, Stash and Commit keys and the raw git output. It covers more cases, but it rebuilds a terminal inside the dashboard, and commit without the secret scan is exactly what Sync exists to prevent.

Under every variant

One new server route, POST /api/git/quick with { dirName, op: "pull" | "push" }. It re-reads the repo, re-checks the rule above, and runs git the way lib/git-fetch.ts already does, behind the same write-access and Answer-token guard. The result shows as one line under the row: Pulled 1 commit into main. or, when git refuses, git refused: your uncommitted change to settings.json would be overwritten. Use Sync.
