Task progress in the chat drawer

Where a session's TaskCreate / TaskUpdate checklist could live. Every variant uses the same example: 13 tasks, 7 done, task 8 running. Each one is drawn three times: the desktop sidecar (290px), the phone band (375px), and the session row badge. Classes are the app's real ones (.kv, .track, .fill, .now, .chat-facts, .ag-pill), so a pick ports straight into styles.css.

A · Gauge card

smallest

A second .kv card styled like Context: the count, a bar, and the running task's activeForm on the .now line. No list.

For: reuses the Context card wholesale, so it is almost no new CSS. Works the same in every theme. Against: it tells you how far along the job is, but not what is left. Most of the red box stays empty.

B · Checklist

recommended

A gauge header over the full list, which fills the red box and scrolls inside it. Done tasks are grey with a check, the running one is highlighted with a pulse, pending ones are hollow. When it opens, the list scrolls to the running task. On a phone the list starts folded to one line, and tapping it opens the list.

For: answers both "how far" and "what's left" at a glance, and it uses the empty space it was asked for. Against: it is the most new CSS of the three, and a 30-task list scrolls inside a 290px column.

C · Segmented track

backlog-manager idiom

One segment per task, in the StageTrack style: the shape of the job at a glance. Below it are the running task and the next one. Tapping a segment puts its subject on the now line (no title tooltip, because it does nothing on touch).

For: one compact unit that reads the same on desktop, phone and row. The row strip shows 13 ticks, not a number. Against: past about 25 tasks the segments get too thin to tap, and you still have to tap each one to find out what it is.

D · Checklist with timings

YAGNI'd

B, plus how long each finished task took, how long the running one has been going, each task's description, and a rough ETA. Drawn here so it can be compared. Left out of the plan.

For: shows where a long job spent its time. Against: it has to pair every status change with the record's timestamp. The ETA would be a guess presented as a number, and the descriptions crowd the 290px column.
