A · Drag grip, always on

recommended

A ⠿ grip leads every pinned row. Drag it (mouse or finger); the order saves on drop, with a quiet “Saved” beside the heading. Keyboard: focus the grip, ↑/↓ moves one place. Grips hide while the filter box has text, because a filtered list has gaps you cannot drop into.

Laptop · card 720px
Phone · 375px
For
  • Direct: the thing you move is the thing you grab
  • Long jumps (5th → 1st) are one gesture
  • Same grip idiom as the other boards on your machine
Against
  • Most code: pointer drag + touch + keyboard path
  • A 28px column costs path width on the phone

B · Up / down buttons

simplest

↑ and ↓ beside each Unpin; the top row’s ↑ and the bottom row’s ↓ are disabled. Each click saves. No drag code at all, works the same everywhere.

Laptop · card 720px
Phone · 375px
For
  • Tiny: two buttons and one swap
  • Accessible by default, no gesture to learn
Against
  • Moving 5th → 1st is four clicks, four saves
  • Three buttons per row is busy; on the phone the path wraps more

C · Reorder mode

calmest at rest

The list looks exactly like today until you press Reorder in the Pinned heading. Then rows get grips and ↑/↓, Unpin and the filter step aside, and Done saves the whole order in one write. Cancel throws it away.

Laptop · card 720px
Phone · 375px
For
  • Resting page unchanged; no stray grabs while unpinning
  • One save, so Cancel is real
  • Phone gets the full width back outside the mode
Against
  • An extra click to start and one to finish
  • A mode is one more state to test

D · Sort modes + drag in Git

YAGNI’d

The bigger version: a Sort select (Manual / Name / Last session) on the Pinned list, and the Git Cards themselves draggable, so you reorder where you actually look at the order. Shown for comparison. Two places that write one order, a sort setting that can silently override Manual, and drag inside Git cards that already hold buttons.
