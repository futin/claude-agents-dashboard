How to read this 6 terms
Weighted rate
Tokens per 1% of the limit, with each token type weighted by what it costs the window. Mix-invariant, so a change here is a real repricing. Drift is judged on this and nothing else.
Raw tokens
The same 1% in plain token counts, at the model's recent mix. Moves when the cache-read habit moves, so it is a translation, not a price.
Fitted
A second estimate of the weighted rate, measured jointly across the windows where several models ran together. Reads more of the evidence, has no baseline yet. The only figure a subagent-only model ever gets.
Baseline
The trailing 14 days before the last three. A verdict needs 7 separate days in it.
Window · pts
One window is one 5-hour limit period that one model owned (≥90% of tokens). pts are the utilization percentage points those windows moved in total.
Across models
Not a price list. A model that fires more requests per token carries that per-request cost inside its rate, so rates compare a model to its own past, not to another model.

B

Annotated rows, definitions on tap

Alternative

No drawer and no intro. Every label carries an ⓘ that opens a small popover with the definition, right where the figure is — a real element that answers hover, tap and keyboard focus, never the title attribute (dead on touch). The verdict legend sits once under the status line. Densest option; explanations are invisible until asked for.

C

One ledger table

Shown to reject

Every model is one row of a single table, headers name every column once, and a column glossary sits under it. The most compact way to compare a model against its own baseline. It is also a desktop layout: at 375px the table scrolls sideways and the verdict, the one thing you asked to lead with, is the first column to leave the screen.
