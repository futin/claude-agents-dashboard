Management · Schedules

The Ledger design, screen by screen: the Jobs page with its stats band, a row's run fold, the Runs page, the New job drawer, the Edit menu and drawer, Run now, and what opens when a run older than the sessions window is clicked. Same five example jobs throughout. Class names are the dashboard's (.mgmt-bar, .seg, .git-chip); new ones are prefixed .sch-.

Screen 1

Jobs, with the stats band for the last N days

Every cell is a stack of short lines and a pill always has a line of its own, so a long duration or a wide pill never pushes its neighbours; pill columns have a fixed width, prose columns ellipsize. The band sums the run log for the chosen window across every job on this machine; the bars are one per day. The ledger row answers the three everyday questions in order: did it work last time, when is the next one, is it on. A row's caret opens the menu (screen 5); clicking the row body unfolds its runs (screen 2).

Screen 4

New job: pick a kind, get a filled-in file, save

One drawer, no wizard. The kind only chooses the template; after that the file is the form. Repos is the one helper above the file: all pinned, a picked subset, or a single cwd; it only rewrites the foreach: line. Name becomes the filename and is checked live. Save validates the frontmatter (cron parses, machines known, runner known, body present), writes schedules/<name>.md, and reconciles; the second button saves it paused, for trying by hand before it is installed. The file is in the git-synced folder, so it reaches the other machine on the next sync.sh push / pull.

Claude prompt, multi-step claude

The body is the whole prompt, as long as it needs to be. One leading /skill line is the "skill" template; anything else is plain claude -p with skills reachable by name.
---
cron: "0 22 * * 0"
machines: [mac]
run: claude
foreach: [claude-agents-dashboard, backlog-manager]
model: opus          # or sonnet, haiku; blank = CLI default
effort: medium
permission-mode: acceptEdits
allowed-tools: [Bash, Read, Edit, Write, Skill]
max-turns: 60
enabled: true
---
Weekly housekeeping for this repo, in order:
1. Run the git-sync skill. Stop here if it reports a diverged trunk.
2. Run docs-sync. Re-baseline only the docs it rewrote.
3. If anything changed, open one `docs:` PR titled
   "docs: weekly sync" and put the docs-sync report in the body.
Reply with one line per step: done, skipped (why) or failed (why).
permission-mode acceptEdits: the run can edit files in each repo without asking. bypassPermissions is refused here.

Screen 5

Editing a job: the caret menu, the same drawer, and what the toggle does

The caret menu holds everything that is not Run now. Edit opens the New-job drawer with the current file, Repos helper included, both ways bound: editing the foreach: line moves the picker, the picker rewrites the line; Save validates, writes, reconciles. The row's toggle rewrites only the enabled: line, keeping the rest of the file byte for byte, then reconciles, so a pause is a one-line diff in git. Delete confirms inside the drawer (the viewer has no confirm dialog) and removes the file plus the installed plist. Reveal opens the folder in Finder / Explorer for people who prefer their own editor; the dashboard picks the file change up by watching the folder.

Screen 5b

Run now, and Run now on one repo

Run now asks the dashboard server to launch the same wrapper launchd would, with trigger: manual; nothing else differs, so a manual run lands in the same log, the same stats and the same Runs page. The row flips at once: pill reads running, the button becomes Stop (SIGTERM to the wrapper, which forwards it to its child). On a fan-out job the caret adds Run now on one repo…: a popover listing the job's repos with each one's last outcome, so the two that failed last night can be rerun without touching the other ten. A step's run again link in the fold is the same thing with the repo preselected. Pause does not block Run now: a paused job can still be run by hand, which is how you test one before enabling it.

Screen 6

Opening a run's session, including one older than the Sessions window

Same path as the Git Sync pill: the run line opens the existing ChatDrawer with the session row, nothing new to draw. One difference underneath: Git Sync gets its row from the Sessions poll, which is capped at 7 days and 50 rows, so a 3-week-old run would come back empty. Here the wrapper chooses the id up front (claude --session-id) and writes it into the run log, and a small by-id endpoint builds the row straight from the transcript file with no window, the way /api/sessions/:id/chat already does. Same drawer, any age.

Mechanics

Reconcile: files in, OS jobs out

Reconcile makes the OS scheduler match the files. It runs on server start, when the folder changes (a pull landed, you edited in your own editor), after every save or toggle from the UI, and from the button. The button shows the diff first and applies on a second click. The chip in the toolbar is its state: in sync, drift 2 (files and installed jobs disagree, e.g. launchd refused a plist), or reconcile failed with the error in the fold. Nothing in the dashboard fires a job; launchd and cron do, through one wrapper script, and they keep doing so with the dashboard closed.
