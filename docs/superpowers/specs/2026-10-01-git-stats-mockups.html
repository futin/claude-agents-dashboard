Sync — one per repo, every layout

phase 2 slot

The button starts a headless /claude-agents-dashboard:git-sync session in that repo through the existing POST /api/spawn. Every decision git-sync asks (push, delete, stash) still comes through the dashboard's remote answers, so nothing happens without your pick. While the session runs, the button reads Syncing · open and opens its chat. When the run ends the card refreshes, since a sync is the one thing that changes "fetched". Repos git-sync would refuse (folder gone, not git, no origin, as with ixray) get no button.

Why not now

/git-sync already prunes inside its own run, and asks first, so a Prune button would be a second path to the same deletion. Sync all would start N sessions at once. PR and CI badges need gh, which is a network call from server/, and test/outbound.test.ts pins those. Branches that exist only on another machine need a fetch here, or the #164 hub.
