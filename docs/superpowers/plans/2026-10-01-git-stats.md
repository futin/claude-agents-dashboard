# Management restructure + Git Stats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Override of the writing-plans template:** this plan specifies behaviour, exact values and exact test *cases*. It never gives literal implementation or test
> code. Write the code yourself from the requirements. If a requirement here looks wrong against the code in front of you, say so instead of transcribing it.
> The line-count budget is soft.

**Goal:** Rename the Claude-config tab to **Claude Configs**. Add a new **Management** tab (Git | Pinned). Fill its Git sub-view with read-only, local git
state for every pinned project.

**Architecture:**
- Phase 0 is a rename plus a nav move.
- Phase 1 adds `server/lib/git-stats.ts`, an async `execFile` reader over the pinned repos. It sits behind `GET /api/git-stats`, with a shape-only contract in
  `shared/types.ts`.
- The client gets pure `lib/` modules (layouts, triage, copy), tested in Node, plus a React sub-view with three layouts and a visible-only 30s poll.

**Tech Stack:** Node built-ins + `tsx` (server, zero deps), React + Vite (client), the repo's node-assert runner (`test/run-all.ts`), real `git` in tmpdir
fixtures.

**Spec:** `docs/superpowers/specs/2026-10-01-git-stats-design.md`. Read it whole before starting any task; every task's requirements include it. Section
references (§n, Dn) below point into it. Mockup: `docs/superpowers/specs/2026-10-01-git-stats-mockups.html`. Where it disagrees with the spec, the spec wins
(spec, "Known differences").

## Global Constraints

- `server/` keeps **zero runtime deps** and makes no new network call: git runs local refs only. Never `fetch`, `pull`, `push`, `gh`, `commit-tree`, or any
  writing command. `test/outbound.test.ts` must stay unchanged and green.
- Every git call is array-form `execFile` with a **5s** timeout and env `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`. Refs are passed as
  full refnames (`refs/heads/<x>`, `refs/remotes/origin/<x>`).
- `shared/types.ts` changes first in any task that adds a field, then the server producer, then the client consumer (repo rule).
- Server imports use the `.js` suffix. Cross-boundary imports are `import type`.
- **CSS class names never change** (e.g. `.wide-mgmt` stays). **No colour or shadow literal** below the theme-token block in `client/src/styles.css`: use
  `--amber`, `--mustard`, `--cyan`, `--green`, `--ink*`, `--hairline*`.
- Nothing under `server/` or `client/src/` imports from `plugin/`.
- Copy strings are exactly the spec's §6 copy table. Do not paraphrase.
- New prose wraps at 160 columns; commit bodies at 72. Conventional Commits subjects. End each commit with the executing session's attribution trailer.
- Records of a moment (`docs/superpowers/**` other than the one note in Task 3, `docs/learning-notes/`) are not rewritten. Do not bump docs-sync `verified:`
  stamps; only edit `sources:` paths when a file moves.
- Work on branch `feat/git-stats` in a worktree; never switch the shared checkout's branch. `pnpm test` and `pnpm typecheck` are green at the end of every
  task.

## Review Focus

1. **A pinned repo mid-rebase or mid-merge with conflicts.** Expected, mid-rebase: HEAD is detached, so `ok` with `branch: null` and `detachedSha` set.
   Mid-merge: HEAD stays on its branch, so `ok` with `branch: 'main'` and `detachedSha: null`. Either way conflicted paths count as uncommitted, and the
   state is never `error`. Pinned in Task 3.
2. **`git` missing from the server's PATH** (a launchd or tailnet start with a thin env). Expected: every repo is `error` with message `git not found`, the
   response is still 200, and the server does not crash. Pinned in Task 5.
3. **Branch names with slashes, dots and non-ASCII** (`feat/ü-x`, `fix/a.b`). Expected: listed by their exact name, with correct ahead/behind. No call
   misreads one as a path or an option. Pinned in Task 4.
4. **The pin set changes between polls** (a pin added, removed or reordered in the Pinned sub-view). Expected: the next poll reflects it in pin order, and
   the memo drops the removed repo's keys. Pinned in Task 5.
5. **A `FETCH_HEAD` mtime in the future** (clock skew between machines that share a checkout over a sync folder). Expected: "fetched 0s ago", never a
   negative age or `NaN`. This is `formatAgo`'s existing clamp. Pinned in Task 6.
