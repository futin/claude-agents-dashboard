# Git Fetch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server runs `git fetch origin` over every pinned repo on a Settings-chosen timer while a Git view is open, plus a manual **Fetch all**, and
Management › Git shows both clocks in a chip beside the layout toggle.

**Architecture:** A new `server/lib/git-fetch.ts` owns the fetch, its per-repo verdicts, the clock state and the timer; `git-stats.ts` only decorates its
payload with them. The client gets one pure module (`gitClock.ts`) for every meter reading and follow-up decision, one hook for the POST, and one component
(`GitClockChip`) for the chip and its popover; the three layouts thread the clock to their "fetched" text.

**Tech Stack:** Node built-ins (`child_process.spawn`, detached), tsx, React + Vite, node-assert tests over `test/git-fixture.ts` repos and the
`test/api-harness.ts` server.

**Spec:** [docs/superpowers/specs/2026-10-02-git-fetch-design.md](../specs/2026-10-02-git-fetch-design.md) — read it first; every task below argues from
its numbered decisions (D1–D13) and sections (§1–§6). The mock is linked from the spec.

**Plan conventions (override the writing-plans template):** this plan specifies **behaviour and exact test cases, never literal code** — signatures,
expected values, edge cases. The implementer writes the code and is expected to disagree with the plan when the code says otherwise. Size budgets in this
plan are soft. Work on branch `feat/git-fetch` off `main`; one commit per task, Conventional Commits, attribution line per the session's reminder.

## Global Constraints

- `server/` stays zero-dep, Node built-ins only; `git-fetch.ts` imports no network module and calls no `fetch(` (`test/outbound.test.ts` `ALLOWED` is
  unchanged).
- `shared/types.ts` first, then server producer, then client consumer. Cross-boundary imports are `import type`; no runtime constant is shared, so the six
  interval values are a literal on each side, each pinned by a test.
- `gitFetchSecs ∈ {0, 30, 60, 120, 300, 600}`, default `0`, a Shared setting read live (never cached by the timer).
- Fetch argv exactly `['-c', 'core.hooksPath=/dev/null', 'fetch', 'origin', '--quiet', '--no-prune', '--no-recurse-submodules', '--no-auto-maintenance']`;
  30s timeout; env overlay `LC_ALL=C`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=''`, `SSH_ASKPASS=''`, plus the D5 ssh rule.
- Spawned `detached: true`, `stdio: ['ignore', 'pipe', 'pipe']`; a timeout kills the process group.
- Watched gate `max(2 × interval, 90s)`; one fetch in flight process-wide; `fetchAll` always resolves.
- CSS: tokens only below the theme block, every new class `git-`-prefixed, no new `@media` breakpoint (reuse `768px`).
- Every user-facing string lives in `client/src/lib/gitStatsText.ts`; components build none.
- Wrap new prose at 160 columns; comments say why, not what.

## Review Focus

Inputs the spec implies but its own test list does not pin; each has a test added to the task named.

1. A hand-edited `.dashboard-settings.json` holding `gitFetchSecs: 45` (or `"300"`) must read back as `0`, not crash the settings store → Task 1.
2. `POST /api/settings {gitFetchSecs: 0}` from a stored `300` must persist `0` — the falsy-value trap in a patch handler → Task 1.
3. Interval set to Off while a fetch is in flight: when it ends `nextAtMs` is `null`, no further fetch starts, the clock reports `intervalSecs: 0` → Task 3.
4. A repo unpinned between two `fetchAll` calls leaves no `lastFetch` entry, so re-pinning it later does not resurrect a stale "needs auth" → Task 2.
5. A payload from an older server with no `fetch` field (dev HMR against a stale API) renders the chip as `…` / `12s`, never throws → Task 6.

  `child.kill` if that throws) and resolves `timedOut: true`; a spawn `error` event **rejects** (so `fetchAll` records `other`). Never a shell.
