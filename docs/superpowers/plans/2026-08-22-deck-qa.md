# Deck Q&A Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tutor decks gain an optional per-section "Questions you might ask" card —
2–4 anticipated learner questions with pre-written grounded answers behind native
`<details>` — and this repo's two decks are retrofitted with it.

**Architecture:** Two prose edits to the **global tutor skill**
(`~/.claude/skills/tutor/`) define the card in the deck contract; then one
content-retrofit pass per existing deck, scoped to section wrappers + restamp, verified
by the contract's own §8 checklist. No dashboard server/client code changes at all.

**Tech Stack:** Markdown (skill contract), hand-edited static HTML (decks), the deck
checklist's grep commands.

**Spec:** `docs/superpowers/specs/2026-08-22-deck-qa-design.md`.

## Global Constraints

- Decks stay network-free: zero new JS, zero `fetch` — the qa card is markup only
  (native `<details>`). Checklist §8 item 5 must still pass untouched.
- Answers follow tutor grounding: every claim cites a real `file:line` in *current*
  code; ≤120 words per answer; no refactoring advice.
- Retrofit edits touch ONLY: content inside `<section id="sN">` wrappers (insertions),
  the provenance stamp, and the recap card's "built at" line. Anything else in the
  byte-diff is a defect.
- Questions are *adjacent confusions* ("why not X instead?", "what happens when Y?") —
  never restatements of quiz questions, never material big enough to need its own quiz.
- The two deck retrofit commits land in THIS repo; the skill edits live under
  `~/.claude/skills/tutor/` (commit there only if `git -C ~/.claude rev-parse
  --git-dir` says it is a repo; otherwise the file edits are the deliverable).
- Repo commits on a fresh branch off `main` (e.g. `docs/deck-qa-cards`) — check the
  dirty tree before staging (house memory: targeted `git add` has swept in-flight work
  before).

### Task 1: Deck contract — define the qa card

**Files:**
- Modify: `~/.claude/skills/tutor/references/deck.md` (§1 structure list ~line 50; §2
  card-type list ~line 88; §7 step 4a; §8 item 3)

**Interfaces:**
- Produces: the contract text Tasks 3–4 implement against. The card's exact markup
  shape (consumed verbatim by the retrofits):

```html
<div class="card card-qa">
  <p class="eyebrow">Questions you might ask</p>
  <details class="qa-item">
    <summary>…one question…</summary>
    <p>…grounded answer, ≤120 words…</p>
  </details>
  <!-- 2–4 qa-item blocks total -->
</div>
```

- [ ] **Step 1: §1 structure.** In the section-wrapper bullet, extend the card run:
  after "2–4 concept cards and 1–2 quiz cards per SKILL.md's Pedagogy", add — in the
  edit's own words but carrying exactly these facts — that a section may additionally
  end with **one optional qa card**, always the last card in its wrapper, because it
  answers questions the section has raised and placed earlier it would leak quiz hints.
- [ ] **Step 2: §2 card type.** Add a sixth entry, **qa card**, after the quiz card
  entry, specifying: the markup shape above; 2–4 items; collapsed by default; no JS
  (native `<details>`, same mechanics as the existing "More detail" block, including
  its overflow test: content that would need its own quiz is a chunk, not a qa answer);
  the adjacent-confusions content rule with the two example phrasings from Global
  Constraints; answers ≤120 words, grounded `file:line`, short labeled `<pre>` excerpts
  allowed under the existing excerpt rule; navigation-inert (an ordinary card in the
  flat list — `Next` never blocks on it, only quiz cards gate).
- [ ] **Step 3: §7 update flow.** One sentence in step 4a: a regenerated section
  regenerates its qa card with the rest of its wrapper; untouched sections keep theirs
  byte-identical. (No mechanism change — this only names the card so §7's "replace the
  wrapper contents" unambiguously includes it.)
- [ ] **Step 4: §8 checklist.** Extend item 3 (currently "No empty feedback") to also
  fail any qa `<details>` whose `<summary>` or body `<p>` is empty/whitespace, with the
  grep `grep -nE '<summary>\s*</summary>|<details class="qa-item">\s*<summary>' <deck>`
  named as the obvious-case catch and a read for whitespace-only, mirroring the item's
  existing structure.
- [ ] **Step 5: Verify + commit.** Re-read the four edits against spec §"What changes";
  confirm §3/§8-items-4/6 (answer-leak machinery) were NOT touched — qa cards have no
  correct option. If `~/.claude` is a git repo: commit there,
  `feat(tutor): define per-section Q&A card in deck contract`.
